# 代码审查检查清单

## 这个文件干什么

审查代码时逐项检查。**不是提示词——是审查标准**。每次 [[../../prompts/04-代码审查-code-review]] 触发时，AI 按这个清单逐项打分。

## 检查维度

### 正确性（致命）
- [ ] 逻辑是否和 RFC/需求一致
- [ ] 边界条件是否处理（空输入、null、0、负数）
- [ ] 错误码是否和 API 契约对齐
- [ ] 异步调用是否正确（有没有漏 await）
- [ ] SQL 参数化是否正确（有没有 SQL 注入）

### 性能（重要）
- [ ] 有没有 N+1 查询
- [ ] 全表扫描还是索引路由
- [ ] 循环里有没有 IO 调用
- [ ] 内存使用是否合理

### 安全（致命）
- [ ] 有没有硬编码密钥/密码/Token
- [ ] 用户输入是否校验
- [ ] 错误信息是否泄露内部细节

### 测试覆盖（重要）
- [ ] 新增代码有没有对应测试
- [ ] happy path 覆盖了
- [ ] 错误路径覆盖了（404/409/422）
- [ ] 边界条件覆盖了

### 代码风格（建议）
- [ ] 对齐项目现有风格
- [ ] 函数长度合理（不超过 ~50 行）
- [ ] 命名清晰、无歧义
- [ ] 无残留 print/调试日志
