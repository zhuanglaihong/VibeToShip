# 01 — 需求夯实

## 这个文件干什么

拿到一个模糊需求之后，让 AI 当面试官反问你，把需求问清楚。**不写代码，只出设计文档**。

## 什么时候用

- 业务方/客户说"我要一个 xxx 功能"，但细节不清楚
- 自己有个想法，不知道边界画在哪
- 你和同事协作前，先对齐理解

## 用什么模型

用 **GPT 5.5（Codex）**——它擅长架构推理和需求分析，适合在实现前澄清边界。

## 怎么用

在 Codex 或 Claude Code 里输入：

```
/grill-me：我要做 [功能]，背景是 [为什么做]，约束是 [不能做什么]
```

## 举个例子

```
/grill-me：我要做农业业务区的气象预报查询接口。前端在地图上选区域，查未来24小时的降水和温度。数据已经在 MinIO 的 Parquet 文件里，每天新增几百万行。约束：PostGIS 只做索引不存明细数据，Phase 1 不支持跨格网混合查询。
```

## 会得到什么

- 这个功能到底做什么、不做什么（边界）
- 数据大概怎么存（表结构草稿）
- 接口长什么样（API 草稿）
- 哪里可能踩坑
- 下一步可以拆成几个小步骤

## 没通过怎么办

如果 AI 追问的问题你答不上来，说明需求还没想清楚。想清楚再回来。
