# Docs — 文档更新工作流

## 核心原则

代码变更和文档同步是同一件事的两面——改了代码，就要改文档。

## 文档更新流程

### 1. 识别影响范围

```bash
git diff --name-only HEAD~1
git diff HEAD~1 -- path/to/file.py
```

### 2. 定位对应文档

根据代码变更类型，找到需更新的文档：

| 代码变更 | 需更新的文档 |
|---------|------------|
| 新增/修改 API 路由 | API 文档（endpoint 列表、请求/响应示例） |
| 修改配置项 | 配置文档 / README |
| 项目架构变更 | README、架构文档 |
| 环境搭建变更 | 安装/部署文档 |
| 公共接口签名变更 | 对应模块文档 + 示例代码 |

### 3. 更新内容

- 保持与代码一致（命令、参数名、返回值）
- 更新代码示例
- 更新 API 请求/响应示例

### 4. 验证

```bash
# 检查文档中的命令是否仍然有效
grep -r "pytest" docs/
```

## 委托策略

| 变更规模 | 处理方式 |
|---------|---------|
| 单文件、1-2 处变更 | 在当前上下文直接完成 |
| 多文件、跨模块变更 | 委托子 agent 批量处理 |

## 强制要求

- 文档更新是代码变更的必要部分，不可跳过
- 如果只修改了文档（无代码变更），在 commit message 中说明原因
