# Review — 代码审查清单

## P0 — 正确性 & 安全（必须通过）

- [ ] 逻辑是否与需求/设计文档一致
- [ ] 边界条件是否处理（空输入、null、0、负数、超范围）
- [ ] 错误处理和错误码是否完整
- [ ] 异步调用是否正确（有无遗漏 await / 竞态条件）
- [ ] 是否避免 SQL 注入、XSS、命令注入
- [ ] 是否硬编码密钥 / 密码 / Token
- [ ] 用户输入是否校验和清理
- [ ] 错误信息是否泄露内部细节

## P1 — 性能 & 架构

- [ ] 是否存在 N+1 查询
- [ ] 循环内是否有 IO / 网络调用
- [ ] 是否有不必要的全表扫描
- [ ] 内存使用是否合理
- [ ] 新增代码是否符合项目现有分层架构

## P2 — 测试覆盖

- [ ] 新增功能有对应测试
- [ ] Happy path 覆盖
- [ ] 错误路径覆盖（404 / 409 / 422 等）
- [ ] 边界条件覆盖
- [ ] 已有测试无回归

## P3 — 代码风格 & 文档

- [ ] 无残留 `print` / 调试日志
- [ ] 无残留无编号 TODO
- [ ] 公共 API 有 docstring
- [ ] 命名清晰、无歧义
- [ ] 对齐项目现有风格（不引入新范式）

## 常用审查命令

```bash
# 查看本次变更
git diff main

# 运行测试
pytest tests/ -v

# 检查硬编码密钥
git diff main | grep -E "(password|secret|token|key)=" | grep -v "^-#"
```

## 审查流程

1. 查看变更概览：`git diff --stat main`
2. 逐文件审查，按 P0 → P1 → P2 → P3 逐项检查
3. 运行测试确认无回归
4. 输出审查结论（通过 / 修改建议 / 阻塞问题）
